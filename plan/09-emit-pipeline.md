**Milestone** v0.1 · **Depends on** 05

> Fragments from every rule, merged per sink, written with a generated header and staleness check.

## Why now

The half of the design that makes editor feedback work without archcheck running.

## In scope

- `Fragment` collection across all rules
- Merge by target into one file per sink
- Generated header naming the manifest and the rules that produced it
- `emit --check` — re-emit to memory, diff against disk, exit 3 on drift

## Out of scope

- The doc emit — plan 19
- The exports-map sink — plan 11, with encapsulation

## Design

**Every generated file opens the same way:**

```js
// GENERATED BY archcheck — DO NOT EDIT
// source: architecture.config.ts
// rules:  domain-no-service-import, rules-are-pure, no-deep-module-imports
// regenerate: npx archcheck emit
```

**Deterministic output.** Sort rules by id before emitting, stable key order in every object. A
re-run with an unchanged manifest must produce a byte-identical file, or `emit --check` becomes a
false alarm generator and gets disabled.

**Statement into the message.** The lint fragment carries the rule's own words:

```js
{ selector: "ImportDeclaration[source.value=/^\\.\\.\\/services/]",
  message: "domain may not import services — invert the call: the service calls the domain" }
```

That is the fix for the biggest problem the review found: the editor shows the architecture's
sentence, not a rule name.
